# HideNSeek

Roblox-проект с синхронизацией через Rojo.

## Первый запуск

Установить закреплённые версии инструментов:

```powershell
aftman install
wally install
```

Один раз установить совместимый плагин Rojo в Roblox Studio:

```powershell
rojo plugin install
```

Запустить сервер синхронизации:

```powershell
rojo serve default.project.json
```

Затем в Roblox Studio открыть плагин Rojo и подключиться к
`127.0.0.1:34872`.

## Команды

```powershell
# Собрать место без запуска Studio
rojo build default.project.json --output build/HideNSeek.rbxlx

# Установить зависимости из wally.toml
wally install

# Проверить Luau-код
selene src

# Проверить форматирование
stylua --check src

# Отформатировать код
stylua src
```

Эти же команды доступны через `Terminal -> Run Task` в VS Code.

## Профиль и валюта

Серверная система в `ServerScriptService/Currency` загружает профиль и показывает баланс
как `leaderstats.Coins`. Менять `IntValue` напрямую нельзя: игровые серверные скрипты должны
вызывать API сервиса:

```luau
local CurrencyService = require(
	game.ServerScriptService.Currency:WaitForChild("CurrencyService")
)

local ok, newBalance, reason = CurrencyService.AddCurrency(player, 1, "CoinPickup")
```

Доступны `GetCurrency`, `CanAfford`, `AddCurrency`, `SpendCurrency`, `AwaitLoaded` и `SaveNow`.
Данные хранятся в расширяемом объекте `Data`, куда позже можно добавить остальные поля
профиля.

Подбор `Coin` начисляет `1` Coins, а `GoldBar` — `3` Coins. Награда выдаётся на сервере,
после чего подобранный предмет удаляется. `MoneyPanelGui.MoneyPanel.BalanceText`
автоматически показывает текущий баланс. После каждого успешного подбора локально
проигрывается `SoundService.GoldSound`.

Для проверки DataStore в Studio нужно опубликовать experience и включить
`Game Settings → Security → Enable Studio Access to API Services`.

## Тестовая админ-панель

Панель открывается клавишей `F2` или кнопкой `ADMIN` и создаётся только для `UserId`, явно
указанных в `ServerScriptService/AdminPanel/AdminConfig.lua`. Сейчас разрешён
`10244668710`. Интерфейс содержит разделы `Overview`, `Economy`, `Player`, `Round` и `NPC`:
можно проверять состояние игрока, добавлять или снимать Coins, сохранять профиль, назначать
роль, лечить/перезапускать персонажа, нормализовать движение, управлять фазой и временем раунда,
а также создавать, удалять и приостанавливать NPC.

Клиентская панель не имеет прямого доступа к игровому состоянию. Для каждого администратора
сервер создаёт отдельный `RemoteFunction`, повторно проверяет allowlist на каждом вызове, принимает
только известные действия и точные схемы параметров, ограничивает частоту запросов и кеширует
результат по `RequestId`, чтобы повторная доставка запроса не выполнила мутацию дважды. Coins
изменяются только через `CurrencyService`, а раунд и NPC — через серверный `RoundControl`.

## Телепорты арен

Внутри каждой арены можно разместить `Folder` или `Model` с именем `Teleport Pads`, содержащий
две детали `Pad1` и `Pad2`. `Pad1` переносит игрока к `Pad2`, а `Pad2` — обратно. Каждая пара
работает только внутри своего контейнера. Игрок появляется в центре площадки над её верхней
гранью, а `SoundService.TeleportSound` проигрывается локально. NPC телепортами не пользуются.

## Случайный Smoke VFX

Шаблон `ServerStorage.Smokes.smoke-01` проигрывается на каждом живом Hider, включая NPC, через
случайные интервалы 3–5 секунд. У Seeker и Spectator эти эффекты отключены. Эффект запускается
одноразовым импульсом. Атрибут `EmitCount` на
каждом `ParticleEmitter` может переопределить количество частиц; по умолчанию выпускается 1.
Таймер эффекта отсчитывает 3–5 секунд только во время движения персонажа и приостанавливается на месте.
Если Hider непрерывно стоит не менее трёх секунд, один раз воспроизводятся
`ServerStorage.Smokes.fart` и серверный пространственный звук `SoundService.FartSound`. После начала движения
эффект бездействия снова становится доступен.

## Раунды

`RoundManager` запускает 15-секундный обратный отсчёт, после которого начинается раунд
длительностью до 60 секунд. Если живых Hider больше не осталось, раунд завершается сразу.
В одном раунде участвуют максимум 8 игроков: до 6 прячущихся и до
2 ищущих. Свободные места заполняются NPC-копиями `StarterPlayer.StarterCharacter`, поэтому в
каждом раунде всегда есть 6 прячущихся и 2 ищущих. И игроки, и NPC с ролью Seeker масштабируются
в 1,5 раза относительно Hider. Лишние игроки ждут следующий раунд как зрители.

Во время фазы `Starting` Hider уже могут разбегаться, а все Seeker удерживаются на месте сервером.
При переходе в `Round` Seeker освобождаются. Hider видят себя, друг друга и NPC Hider, но для
Seeker и Spectator их тела невидимы до обнаружения. Попавший в клетку Hider сразу становится
видимым всем; после спасения снова скрывается. Smoke, Fart, LeaksVFX, свет, следы и звук
не отключаются. Для будущей VFX-геометрии, которая должна остаться видимой, можно
установить атрибут `RoundPreserveVisualWhenInvisible = true`.

`Workspace.HUB.SpawnHUB` используется как хаб. Внутри каждой арены должна находиться
одна деталь с точным именем `SpawnArena`. Перед началом сервер выбирает одну арену и размещает
всех участников и NPC возле её `SpawnArena`; зрители, вошедшие во время активного раунда и
переведённые в `Spectator` игроки находятся в хабе. Респавн во время раунда возвращает активного
Hider/Seeker на ту же арену. Если ни одного корректного `SpawnArena` нет, раунд остаётся в
`Waiting` и не использует хаб как запасную игровую точку. Размер `SpawnArena` задаёт безопасную
область появления; для восьми раздельных мест рекомендуется свободная площадка не меньше
`18 x 18` studs без стен внутри.

`RoundTimer` создаёт общий верхний интерфейс с синхронизированным таймером, фазой раунда,
занятыми слотами обеих ролей и ролью локального игрока.

Навигация NPC автоматически строится из `Map/Floor` и `Map/Walls`. Сервер один раз превращает
повёрнутые детали стен в расширенные 2D-препятствия, вычисляет виртуальные углы и стыки, соединяет
видимые точки и прокладывает маршрут через A*. `ArenaBounds`, ручные `NPCPath` и
`PathfindingService` для этого не используются. Все отрезки дополнительно проверяются на полное
покрытие объединением деталей `Floor`, поэтому NPC не может срезать путь через отверстие в полу
или пройти сквозь расширенный контур стены.

NPC появляются с временно закреплённым `HumanoidRootPart`, сразу выравниваются над поверхностью и
отпускаются в физику после одного кадра. Для них используется отдельная collision group, поэтому
они не сбивают друг друга и игроков. `NpcAnimator` загружает `idle` и `run`/`walk` Animation из
`StarterPlayer.StarterCharacterScripts.Animate` на серверном `Animator`.

Скорость всех персонажей равна 13 studs/s независимо от масштаба, а NPC получают разные цвета из
палитры. Параметры раунда находятся в `Round/RoundConfig.lua`, а параметры навигации Hider — в
`Round/HiderConfig.lua`.

## Поле поиска Seeker и поимка

Во время фазы `Round` вокруг каждого Seeker отображается оранжевое поле: круговой радиус
составляет 3 studs, а ровно 16 передних сегментов из 64 имеют длину 6 studs и образуют сектор
90 градусов по направлению взгляда. Клиент обрезает каждый сегмент ближайшей
деталью внутри `Map/Walls`, другим физическим препятствием или закрытыми воротами. Детали из
`Map/Walls` считаются стенами даже при `CanCollide = false`. Сервер независимо проверяет ту же дистанцию и прямую
видимость, поэтому клиентский визуал не участвует в принятии решения о поимке.

Попавший в видимую область Hider на 10 секунд оказывается внутри серверной модели
`ServerStorage.cage` и не может двигаться. Другой живой Hider вне клетки может автоматически
освободить его, находясь не дальше 3 studs с прямой видимостью непрерывно 0,75 секунды.
После спасения действует двухсекундная защита от повторного попадания в клетку.
Если спасения не произошло, реальный игрок становится `Spectator` и переносится на
`Workspace.HUB.SpawnHUB`; модель пойманного NPC удаляется с арены, но его слот остаётся в
состоянии `Caught` до конца раунда. Пойманные места автоматически не заполняются новыми NPC.

Состояние `Caged` хранится на сервере и переживает Reset Character. Клетка пересоздаётся вокруг
нового персонажа, а над ним показываются английский таймер и прогресс спасения. Модель должна
лежать в `ServerStorage` под точным именем `cage` и быть классом `Model`. Необязательный потомок
`HiderPosition` (`Attachment` или `BasePart`) задаёт точную точку персонажа внутри клетки; без него
позиция Hider совмещается с устойчивым центром основных деталей клетки, а нижняя грань ставится
на уровень его ног. Двери, петли и невидимые вспомогательные детали центр не смещают. Все параметры находятся в
`ReplicatedStorage/SeekerSearchConfig.lua`. Studio-only модель сохраняется при live-синхронизации
Rojo благодаря `$ignoreUnknownInstances`, но для чистой самостоятельной сборки её нужно отдельно
экспортировать и добавить в Rojo-проект.
